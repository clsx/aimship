# Align this delivery

## Basis

Read the user commission, current/adopted requirements, source versions and proposed engineering objects.

## Work and result

Record this goal, included/excluded requirements, source mappings, endpoint, authorization boundaries and acceptance. Explain external conflicts and adoption decisions. After associating or changing code scope, use the [recorded-overlap check](../core.md#independent-deliveries-and-recorded-overlap). Record actual checkout locations and read-only versus intended write scope. Agree the ordered stages based on gaps; keep stage progress only in state. Self-owned requirements may carry this information.

## Continue when

The goal, authority and scope are clear enough for the selected next work, with relevant decisions resolved or dependent work held.

## Decisions and blockers

Material conflicting sources or uncertain authority needs clarification; format differences alone do not. Never choose source priority by filename or date.

Use [the shared core](../core.md) for state, evidence and continuation rules. Record meaningful results in an artifact or referenced section; a file alone is not completion.
