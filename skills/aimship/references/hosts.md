# AI tool access

The project workspace is the AI tool's working context; it need not contain a code repository. Use the actual delivery directory in place. If needed, ask the user to add that directory to the workspace or grant access through supported controls, without copying materials. Do not claim to know folder membership or automatically add folders when the tool provides no such evidence. Code location is needed only for work that uses code, not for initialization.

Reuse the current session's access when normal file operations succeed. A successful read does not prove write access; check the actual save result before reporting persistence. Do not create probe files, rescan all permissions every stage or treat a second project as permission for the current conversation. Keep the materials directory separate from repository roots and set the correct working directory for engineering commands.

When access is missing, name the exact delivery/repository path and the needed operation. Retain the original request and continuation context. Do not disable AI tool permission controls, grant the entire home directory or silently move materials into the repository.

- Codex: explicitly select Aimship (CLI `$aimship`). If CLI startup is needed, verify the executable/version/help and use its supported `--cd` and repeated `--add-dir` syntax for the needed writable directories. For desktop, rely on the actual current interface or official guidance; never invent a directory button or claim a prepared path has been granted access.
- Cursor: explicitly use `/aimship`. When useful, prepare `.aimship/host/cursor.code-workspace` inside the delivery with absolute `folders[].path` entries only, referencing materials and repositories; preserve an existing workspace's settings. The user opens/adds folders when necessary. For CLI verify the exact executable (do not assume bare `agent` is Cursor) and current `--workspace` / `--add-dir` support.
- Claude Code: explicitly use `/aimship`; verify current `/add-dir` or `--add-dir` behavior when additional access is needed. Do not fork the skill or start a subagent.

Installation discovery, actual selection, model behavior, directory access and continuation are separate evidence levels. Codex/Cursor share the managed `.agents/skills/aimship` entry; Claude Code uses `.claude/skills/aimship`. An AI tool may discover both, including when it is not registered with Aimship. Registration controls installer-managed connections, not another AI tool’s compatibility scanning. Managed entries must point to the same stable installation; do not assume duplicate precedence or delete unrelated entries. Record duplicates as observed, and consult the published support matrix for tested surfaces.

After compaction or manual switching, reload the fixed-version core, state and current-stage inputs if missing. Do not rely on an AI tool retaining all Skill text. If even the binding location is absent, request the delivery path. Re-invoking an entry to restore context continues the existing delivery; it does not create another one.

When changing AI tools, use the same delivery directory and state; do not duplicate requirements or design to establish a new session. Permissions must be granted separately in each AI tool. Keep one writing tool/session for the delivery. User-facing entry/reload and lifecycle instructions are in [the user guide](../../../docs/guide.md#hosts).

Do not move or replace a user-owned workspace. Check the actual directory identity and access before continuing.

For initialization, materials access is sufficient; code may be associated later. Reuse an existing project’s access, not its directory as the delivery destination. Use a separate delivery folder under bind’s dataRoot unless the user explicitly selected another location. Supplying an existing prototype or opening its project is not that choice; preserve and associate the material at its actual location. When a new target folder cannot yet be opened, guide the user to the existing parent or to create/open the intended folder, according to actual tool capabilities. Preserve unsaved input before any session switch. Recheck necessary access in the new session; a project name is not evidence of permissions. If the configured location remains inaccessible, report the blocker without saving the delivery in a fallback directory. Follow the core’s initialization receipt after the actual save.

For an unreleased source trial, explicitly read the checkout Skill and bind its package-root CLI. Verify releaseRoot/corePath/cliPath and the returned fixed CLI’s help/schema, not just the package version: local edits may retain the published version number. Do not fall back to a cached installed Skill. Loading the source manually does not establish AI-tool automatic discovery.
