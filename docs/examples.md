# Executable synthetic examples

From a source checkout, run `node scripts/run-examples.mjs <new-output-directory>`. The directory must not exist. The harness creates isolated code and delivery folders, exercises actual functions with Node assertions, and saves readable formal documents plus internal state/evidence. It does not install Aimship, touch user deliveries, access the network or publish anything.

The single-batch commission authors a PRD for line normalization, completes plan before implementation, uses one review for batch and overall scope, and runs independent normal/empty/error assertions. It updates the same plan for execution and the same testing document for cases and RUN results.

The adopted multi-batch commission preserves a catalog PRD and prototype reference, maps the source namespace in Scope, implements shared price validation then quoting, and performs each batch's review. A synthetic change adds a discount requirement without rewriting the source. It retains case v1, writes v2, marks affected earlier review applicability, and checks exact code hashes. A deliberate rounding fault exercises a failing RUN; repair review and a new RUN retain the failure. The shared business rule, single-role access restriction and bounded performance requirement have independent identity and acceptance.

These are local examples of the new document/state protocol. They do not establish automatic Skill discovery, actual cross-host continuation, UI interaction or HTTP acceptance. Run output includes exact assertions and limitations. The [document rules](../skills/aimship/references/document-patterns.md) describe other input conditions and the [CLI protocol](cli.md) describes migration and view fault handling.
